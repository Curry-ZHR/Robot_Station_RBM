# 部署边界：开发机与机器人

## 原则

机器人是共享设备。所有不要求直接访问机器人硬件、且不承担本地执行保护职责的程序，优先部署在 4070 开发机。机器人端仅保留必要的硬件接入、动作执行与保护服务。

下表是后续开发约定，尚不代表现有代码已经完成远程部署改造。

| 功能 | 部署位置 | 原因 |
| --- | --- | --- |
| Station 前端、后端、任务编排 | 开发机 | 集中操作与维护 |
| 模型推理、动作生成 | 开发机 | 使用开发机 GPU |
| 离线回放、可视化、质检、数据转换 | 开发机 | 无需直接访问硬件 |
| ROS 2 操作节点、订阅与指令发布 | 开发机 | 通过有线网络访问机器人 ROS 接口 |
| CAN、串口、USB 设备驱动及硬件 SDK | 机器人 | 直接访问机器人本机设备 |
| 硬件驱动 ROS 节点、执行服务及其启动入口 | 机器人 | 将本地硬件暴露为可访问的接口 |
| 指令时效校验、断线保护、执行限幅 | 机器人 | 网络或开发机故障时仍需生效 |
| 数据录制 | 优先开发机，按实测决定 | 若原始相机数据带宽或完整性要求无法满足，机器人端仅保留必要录制服务 |

ROS 2 本身支持分布式节点；并非全部 ROS 程序都必须部署在机器人上。部署位置由是否需要访问本机设备及承担本地保护来决定。

## 操作入口

操作员可以从开发机触发机器人端必要服务的启停。远程触发不改变服务实际运行的位置；硬件驱动及设备配置仍在机器人端执行。

共享机器人只允许一个控制任务获得执行权。获取控制权、释放控制权、指令超时及远程断开后的行为需要由机器人端执行服务落实，不能只依赖开发机界面。

## 当前代码需要适配的部分

- 服务管理目前通过本机子进程启动驱动，需增加机器人端服务的远程管理能力。
- CAN、设备和磁盘自检需分别报告开发机与机器人端结果。
- 两端需准备兼容的 ROS 2 环境、消息定义、DDS 网络配置及 QoS。
- 数据录制位置需在连接真实设备后，根据图像吞吐、丢帧和时间同步结果确定。

开发机部署 Station 不应默认在共享机器人上启动整套工作台，也不应默认接管机器人或改动其他使用者的服务。
