## 用户确认的完整三件套与12GB最低目标

2026-10-20用户明确：最终将**SONIC包 + Robot Station控制网页及后端 + XRoboToolkit**一起打包，让其他人在不同开发机上快速部署、开箱使用；**最低显存目标12GB**。这是待实现、待实测的最终交付要求，当前没有制作或验收完整安装包。

最终交付可采用一个归档包/统一分发目录，其中包含工作台`.deb`、SONIC Docker离线镜像/权重/资源、XR运行时及统一安装器；内部允许分层升级，但用户从同一个入口完成整套部署，不要求先复制原4070目录或手工重建Python环境。保留匹配的PICO客户端安装文件（在可分发范围内）或官方获取入口、版本及配置步骤。

| --- | --- |
| SONIC | 固定版本控制程序、策略与规划模型、Docker运行环境、MuJoCo、PICO Manager及可重建依赖 |
| Robot Station | 网页/后端、Unitree SDK适配、ROS2图像桥接、采集/回放/转换、配置自检、run.sh/stop.sh和systemd入口 |

12GB最低目标覆盖SONIC遥操作/仿真与工作台运行，须在12GB显存开发机上测量实际组合负载、峰值显存/余量、预览与姿态频率、采集稳定性。任务大模型仍可在HPC/4090推理，4070作为接入、预览、采集及动作下发端；完整GR00T N1.7本地推理能力另行验证，不能由本要求推定为已支持。

显存容量只是支持条件之一；发布时要给出经过验证的Ubuntu/CPU架构/GPU架构/驱动/CUDA与TensorRT组合。引擎缓存按目标机能力生成或选用，不能把4070专属TensorRT缓存作为所有GPU通用产物。CPU、内存、磁盘和最低驱动版本由后续实测确定，不填未经验证的最低参数。

## 两种使用方式

1. **访问现有4070**：同一可达网络里的电脑直接用浏览器打开 `http://192.168.123.100:9999/`，无需安装SDK或桌面客户端。操作权限仍由工作台授权管理。
2. **在另一台Ubuntu工作站连接自己的机器人**：安装完整运行端，配置该机器的机器人网卡、DDS域、相机话题和资源路径，后台服务启动后浏览器打开本机地址。每台机器人单独核验硬件和参数。

## 首选交付形式

- Ubuntu首版采用 `.deb` 安装包：网页静态资源、后端、启动/停止工具、服务定义、依赖版本清单与必要SDK集成。安装后提供“打开G1工作台”入口，保留服务自启动与有序关闭。
- SONIC镜像、模型和XRoboToolkit大体积资源可分层维护，但最终须随完整三件套交付，统一安装器校验版本/完整性；界面更新可仅更新应用层，无需每次重发全部资源。
- 首次启动向导完成环境/架构/驱动检查、机器人网卡及IP、Unitree域、ROS相机域/话题、数据目录配置。安装器不能承诺跨任意Ubuntu、CPU架构和NVIDIA驱动直接兼容，先明确支持组合并在干净系统验收。
- AppImage适合以后提供便携启动器，但常驻服务、ROS/DDS与GPU依赖仍需处理；当前首选deb。Windows电脑作为浏览器访问端无需exe；若将来需要独立Windows机器人运行端，应作为新的平台适配任务。
- 分发包不包含操作密钥、Cookie/会话、真机标定授权、机器指纹/开机绑定、个人采集数据；目标机器首次启动生成自己的操作密钥，并保持运动关闭。
- 完成版本锁定、资源清单、可重复构建、安装/升级/回滚/卸载保留数据策略后，在干净Ubuntu环境测试，再生成校验和和发布说明。实际上传发布需要届时指定分发位置。

当前 `run.sh`/`stop.sh` 是已部署4070上的统一生命周期入口。最终安装包会包含并调用这些能力；单独复制run.sh不足以携带全部环境和模型。
